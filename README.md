## Ludora 是什么？

Ludora 是一个运行在 Mac 上的 AI 游戏制作工作台。你说出想做的游戏，它调用 Codex 帮你整理玩法、编写代码、准备素材和检查结果。你可以在工作台里试玩，再用对话继续修改。

它适合从简单游戏开始练习，比如跳跃闯关、收集星星、太空射击。第一次不用先读懂所有代码，也建议先做一个小关卡，不要一开始就做大型游戏。

注意区分：**Ludora 是制作工具，你做出的游戏是另一个独立项目。** 游戏文件保存在你选择的本地文件夹里，可以继续编辑，不是只能在 Ludora 中使用。

### 能做什么，不能做什么？

- **描述创意**：用中文说明玩法、画面风格、操作方式和胜负规则。
- **生成与修改**：让 AI 编写游戏代码，接入图片、音频等素材，再按你的反馈调整。
- **边做边看**：在同一工作台查看预览、制作记录、文件和素材；需要授权时会出现审批提示。
- **继续旧项目**：从项目列表打开之前的游戏，接着制作。

当前主要面向 **macOS 和浏览器小游戏**，不是 Unity、Unreal 或 Godot 编辑器，也不会自动帮你上线网站或发布到应用商店。AI 生成后仍需要你试玩，质量不保证一次到位。

## 第一步：把应用启动起来

### 1. 准备好这些

- 一台 Mac。
- [Node.js](https://nodejs.org/) 和 npm，建议使用 Node.js 22。安装 Node.js 时会一起安装 npm。
- 可联网的环境，以及能正常使用 Codex 的 ChatGPT 账户。

Ludora 不附送 Codex 或第三方素材服务的使用额度。实际能否生成，取决于你的账户权限、剩余额度和服务配置。

### 2. 安装并运行

下载或克隆本仓库后，在项目文件夹中打开终端。**确认这个文件夹里有 `package.json`**，再依次运行：

```bash
npm install
npm run dev
```

第一条命令安装项目需要的工具，首次运行时执行；第二条命令打开 Ludora 桌面应用。以后启动通常只需要 `npm run dev`。

开发模式运行期间请保留这个终端。想结束开发服务时，在终端按 `Control + C`；如果正在制作游戏，先在应用中停止任务。

### 3. 登录并检查图片能力

打开 **设置 → Codex 账户**，按提示登录 ChatGPT。即使你在其他 Codex 工具里登录过，也可能需要在这里单独登录：Ludora 使用自己的账户配置目录。

制作游戏还需要一种可用的图片生成方式：

- Codex 自带的图片生成能力（ImageGen）；或
- 在 **设置 → 媒体 API** 中配置图片服务。

两种都不可用时，应用会提示你先配置，不能直接开始制作。外部媒体服务需要填写相应的服务地址、模型和密钥；不要把密钥写进游戏代码或提交到 Git。

## 第二步：做出第一个小游戏

1. 打开 **创作首页**，输入下面的示例。
2. 确认保存位置，模型、推理强度和帧率先保留默认值。
3. 点击 **开始制作**。应用会创建游戏文件夹，并进入工作台。
4. 查看制作记录；出现审批时，先读清楚要执行什么，再决定是否允许。
5. 游戏生成后试玩。有不满意的地方，在右侧输入具体修改要求，再点击 **继续制作**。

可以直接复制这段：

> 制作一个俯视角收集游戏。用方向键移动，收集 5 颗星星获胜，碰到敌人失败。失败或获胜后可以重新开始。画面简洁，先做一个能完整游玩的小关卡。

之后一次改一个点，例如：

> 敌人移动太快了，请降低速度，其他规则保持不变。

> 增加一个分数显示，每收集一颗星星加 10 分。

比起“做得更好玩”，这种明确的要求更容易检查是否改对。

### 工作台怎么看？

- **左侧项目栏**：找到和切换你的游戏。
- **中间预览区**：试玩游戏；顶部的“素材”和“文件”可以切换查看对应内容。
- **右侧制作对话**：看制作记录、提交修改、停止任务。“查看详细日志”可以展开更多技术信息。
- **流程行**：默认只显示当前阶段和步数，例如 `代码实现 · 6 / 8`。点击展开完整八阶段流程，再点击收起。
- **高级设置**：按需调整模型、推理强度和 30 / 60 / 120 FPS 目标，新手可以先不改。

目前界面只保留深色主题。新游戏还没做出来时，预览里显示的是静态宣传图，不是可玩的游戏，也不是视频。

## 它在背后怎么做游戏？

可以把它理解成一组分工不同的 AI：

1. **规划**：先读你的要求和现有文件，决定要做什么。
2. **制作**：写代码、准备素材，把玩法接起来。
3. **检查**：核对实际文件和运行结果；发现问题时，最多再修复一次并复查。
4. **交付检查**：应用确认必要素材已生成并接入游戏，通过后才标记完成。

界面上的八个阶段只是制作进度提示。`6 / 8` 不代表已经花完 75% 的时间，也不等于游戏已经通过检查。

游戏通常使用 HTML、CSS、JavaScript / TypeScript：简单说，HTML 搭页面，CSS 管外观，JavaScript / TypeScript 控制移动、碰撞、得分和胜负。这些都是普通网页技术，不是特殊的“AI 游戏格式”。

## 常见问题

### 为什么一直显示宣传图，或者制作停下来了？

宣传图是新项目的等待画面。先看右侧的任务状态和制作记录：可能仍在生成，也可能需要审批、账户额度不足、素材服务失败，或检查没通过。不要只凭预览图判断是否完成。

### 一定要配置所有素材服务吗？

不用。**图片生成能力是必需的**，当前项目要求游戏实际使用至少一张经过校验的 AI 生成图片。音频、3D 等服务按需要配置；没有外部图片 API 时，可以使用可用的 Codex ImageGen。

外部服务的配置检查通过，也不代表每次生成都会成功，仍可能遇到余额、模型权限或服务错误。先做简单的 2D 游戏更容易入门；3D 服务目前还有接口适配限制，详见[架构文档](docs/ARCHITECTURE.md)。

### Reasoning Effort 和 FPS 是什么意思？

- **Reasoning Effort（推理强度）**：AI 思考任务时投入的力度，不是游戏画质。先用默认值；复杂任务再考虑提高，可选项随模型变化。
- **FPS（目标帧率）**：希望游戏按每秒多少帧的目标设计。默认 60 即可。选 120 不等于每秒生成 120 张图片，也不保证实际运行一定达到 120 帧。

### 提示词和 Skill 可以改吗？

可以。提示词是给 AI 的要求，Skill 可以理解为它执行任务时参考的操作手册。

- **设置 → 提示词**：修改规划、制作、检查、修复环节的补充要求，例如“所有按钮用中文”。
- **设置 → Skills**：管理可用技能；标为必需的图片生成技能不能停用。
- **游戏文件夹**：可以编辑 `GAME_DESIGN.md`（玩法说明）、`AGENTS.md`（项目要求）和 `.codex/skills/noobi-game-builder/SKILL.md`（制作手册）。

这些要求不能覆盖应用固定的权限和素材校验规则。新手先改设置中的补充提示词即可，MCP 等工具扩展可以以后再学。

### 想从零学代码，先看哪里？

先在工作台点击 **在 Finder 中显示**，找到你生成的游戏文件夹，不是 Ludora 的源码文件夹。

通常先看 `GAME_DESIGN.md` 了解规则，再看 `src/main.js` 中的游戏逻辑、`src/style.css` 中的样式和 `index.html` 页面入口。AI 可能调整文件结构，以你的实际项目为准。

建议先手动改一次速度、颜色或分数，再让 AI 做一个小功能，对比它改了哪些文件。生成项目自己的 `README.md` 和 `package.json` 会说明如何单独运行和构建游戏。

## 想修改 Ludora 本身？

<details>
<summary>展开查看代码入口和开发命令</summary>

Ludora 使用 Electron 运行桌面窗口，React + TypeScript 构建界面，通过 Codex App Server 调用 AI。先根据你想改的内容找文件，不必通读整个项目。

| 想改什么 | 从这里开始 |
| --- | --- |
| 颜色、间距、字体和布局 | [workbench.css](src/renderer/workbench.css) |
| 创作首页 | [HomeWorkspace.tsx](src/renderer/components/HomeWorkspace.tsx) |
| 预览、对话、流程与设置 | [界面组件目录](src/renderer/components/) |
| AI 规划、制作、检查的流程 | [gameHarness.ts](src/main/gameHarness.ts) |
| 新建游戏时的初始文件和项目指令 | [workspaceTemplate.ts](src/main/workspaceTemplate.ts) |

`src/generated/codex/` 和 `schemas/codex/` 是自动生成的通信格式说明，不是数百个产品功能，通常不需要手改。部分内部名称仍保留 `noobi`，用于兼容旧项目和工具，不要直接全局替换。

在 **Ludora 源码目录** 运行：

```bash
npm run typecheck        # 检查代码类型
npm test                 # 运行自动化测试
npm run verify           # 类型检查、测试和正式构建
npm run package:mac      # 生成 macOS DMG，输出到 release/
```

界面验收使用隔离的演示数据，不调用真实 AI：

```bash
env -u ELECTRON_RUN_AS_NODE npm run smoke:reference
```

截图输出到 `.ludora-smoke/reference-after/`。项目清理命令会删除这些临时截图。

`smoke:codex`、`smoke:harness`、`smoke:media` 等真实服务检查可能消耗账户或 API 额度，不是入门必做步骤。

目前只配置了 macOS 打包，尚未提供 Windows / Linux 发布流程。DMG 要正式向公众分发，还需要配置 Apple 签名和公证。

</details>
