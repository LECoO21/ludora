# Ludora UI 与首页简化技术排期手册

> 文档版本：V1.0
> 编写日期：2026-09-04
> 计划周期：6 个工作日 + 1 个缓冲日
> 实施范围：Ludora 桌面端 Renderer（React + TypeScript + CSS）

## 1. 这次要做成什么

用一句话概括：

> 打开 Ludora，输入一个游戏创意，点击“开始制作”，然后在项目页一边看 AI 制作，一边在右侧试玩。

本次改造的重点不是增加更多能力，而是把已有能力重新排列，让第一次使用 Ludora 的人也能马上理解。

最终界面分成两层：

1. **首页**：创意输入框、开始制作、最近项目。
2. **项目工作台**：左边项目、中间制作过程、右边游戏预览。

## 2. 当前项目基线

### 2.1 已有技术能力

- Electron 桌面应用。
- React + TypeScript Renderer。
- Codex App Server 登录、模型读取和 Agent 执行。
- Planner、Implementer、Reviewer、Repair 制作流程。
- 游戏项目创建、继续制作、停止运行。
- 图片、音频、3D 素材能力。
- 本地游戏预览、素材库、项目文件查看。
- 项目列表、设置、审批、错误提示和明暗主题。

### 2.2 当前 UI 的主要问题

- 首页更像宣传页，不像一个可以马上开始工作的页面。
- 首页的 `IDEA / BUILD / PLAY`、统计指标和大标题占用了大量空间。
- 项目页同时展示 8 个流程卡片、事件流、参数、预览、素材和文件，信息密度过高。
- 模型、Reasoning、FPS、图片要求直接暴露，对新手不够友好。
- Thread ID、方法名、全大写英文和等宽字体较多，视觉上接近开发者控制台。
- `styles.css` 约 3900 行，修改时需要严格限定选择器范围，避免影响设置页和审批弹窗。

## 3. 已确认的产品方向

### 3.1 首页结构

首页只保留以下内容：

```text
Ludora
Turn ideas into playable worlds.

┌──────────────────────────────────────────┐
│ 描述你想做的游戏……                       │
│                                          │
│ 示例：制作一个躲避陨石的太空射击游戏     │
└──────────────────────────────────────────┘
                         [开始制作]

最近项目
[项目 A] [项目 B] [项目 C]
```

删除或隐藏：

- `IDEA / BUILD / PLAY` 装饰。
- `ONE PROMPT · PLAYABLE OUTPUT` 等技术式标语。
- Pipeline、Runtime、Media、Projects 四个统计指标。
- 首页大段产品介绍。

### 3.2 项目工作台结构

```text
┌──────────┬────────────────────────┬────────────────────┐
│ 项目列表 │ 项目名 + 简化进度      │ 游戏预览           │
│ 可收起   │                        │                    │
│          │ AI 对话 / 制作记录     │ 预览 / 素材 / 文件 │
│          │                        │                    │
│          │ 创作输入框 [开始/停止] │                    │
└──────────┴────────────────────────┴────────────────────┘
```

具体调整：

- 左侧项目栏保留，但支持收起。
- 中间保留事件流和输入框，作为主要创作区域。
- 右侧默认显示游戏预览；素材和文件继续作为 Tab 保留。
- 8 个 Pipeline 卡片改成一条紧凑进度条，只突出当前阶段。
- Composer 默认只显示输入框和执行按钮。
- 模型、Reasoning、FPS、图片要求放进“高级设置”。
- Thread ID、事件方法名和长技术内容放进“详细日志”。
- 顶栏只保留项目名称、项目状态和设置入口；Finder 等低频操作收入更多菜单。

### 3.3 视觉方向

- 风格：简洁、友好、有创作感的工作室界面。
- 保留 Ludora 品牌图标和明暗主题。
- 减少边框、全大写英文、等宽小字和重复状态。
- 用留白、字号和层级区分信息，避免每块内容都做成卡片。
- 主色只用于“开始制作”、当前进度和重要状态。
- 动效保持轻量，并继续兼容 `prefers-reduced-motion`。

## 5. 首页关键流程

### 5.1 正常流程

1. 用户在首页输入游戏创意。
2. 点击“开始制作”。
3. Renderer 使用默认工作目录、默认模型和 60 FPS 创建项目。
4. 项目名称默认取创意中的前一小段；用户可以在高级设置中修改。
5. 创建成功后进入项目工作台。
6. 复用现有 `runProject` 接口自动启动 Agent。
7. 中间显示制作过程，右侧逐步显示游戏预览。

本流程只编排现有 `createProject` 与 `runProject` 能力，不新增 IPC。

### 5.2 前置条件不满足

| 状态 | 首页处理方式 |
| --- | --- |
| 未输入创意 | 禁用“开始制作”，提示“先写下你的游戏想法” |
| Codex 未登录 | 显示“登录 Codex 后开始制作”，点击后进入账户设置 |
| Runtime 未就绪 | 显示当前错误和“检查运行环境”入口 |
| 图片能力不可用 | 显示“配置图片能力”入口，不让任务进入必然失败状态 |
| 默认工作目录无效 | 打开精简设置，让用户选择保存位置 |
| 创建项目失败 | 保留用户输入，并显示可读错误，不清空内容 |
| Agent 启动失败 | 项目仍然保留为草稿，允许用户再次启动 |

### 5.3 高级设置

首页和项目 Composer 的高级设置统一包含：

- 项目名称。
- 保存位置。
- Agent 模型。
- Reasoning Effort。
- 目标 FPS。

默认折叠。普通用户不需要理解这些选项，也可以完成第一次制作。

## 6. 技术改造方案

### 6.1 主要文件

| 文件 | 计划调整 |
| --- | --- |
| `src/renderer/App.tsx` | 首页状态、创建后自动启动、顶栏精简、工作台结构编排 |
| `src/renderer/components/HomeWorkspace.tsx` | 新增首页创意输入、示例、前置状态和最近项目 |
| `src/renderer/components/ProjectRail.tsx` | 增加桌面端收起状态，简化底部运行时信息 |
| `src/renderer/components/Pipeline.tsx` | 8 卡片改成紧凑进度条，保留原阶段数据 |
| `src/renderer/components/EventStream.tsx` | 默认突出用户可读信息，技术字段进入详细日志 |
| `src/renderer/components/Composer.tsx` | 默认只显示创作输入和按钮，高级参数折叠 |
| `src/renderer/components/Inspector.tsx` | 保留预览、素材、文件功能，降低工具栏视觉重量 |
| `src/renderer/components/NewProjectModal.tsx` | 改成高级创建入口或复用为缺少必要信息时的补充表单 |
| `src/renderer/styles.css` | 新首页、三栏布局、收起状态、响应式和视觉层级 |
| `src/renderer/ui.ts` | 如有需要，只增加纯展示辅助函数和可读标签 |

### 6.2 明确不改的区域

- `src/main/`
- `src/shared/contracts.ts`
- `src/generated/codex/`
- `schemas/codex/`
- 项目级 `AGENTS.md` 和 `.codex/skills/`
- 设置中的 Prompt 与 Skill 数据

如果实施中发现必须修改这些区域，应先暂停并重新评估，不直接扩大范围。

### 6.3 状态管理原则

- 继续使用 React 现有 `useState`、`useMemo` 和回调，不引入 Redux 等新依赖。
- 首页输入单独保存，在创建或启动失败时不得丢失。
- 自动开始分成“创建成功”和“Agent 启动成功”两个状态，不能把两者混为一次不可恢复操作。
- 项目栏收起状态本期只保存在当前会话；如果以后需要跨启动记忆，再扩展设置。
- 所有权限、登录和媒体能力判断继续使用现有 `runtime` 与 `settings` 数据。

### 6.4 CSS 实施原则

- 本期不做与 UI 目标无关的全量 CSS 重写。
- 新样式使用明确的页面级前缀，避免污染设置弹窗和审批弹窗。
- 保留现有 CSS 变量和明暗主题，不复制两套颜色。
- 断点按真实布局需求调整，不按设备名称硬编码。
- 桌面宽屏显示三栏；中等宽度优先保留中间创作区和预览；窄屏改为单列和可切换面板。

## 9. 验收标准

### 9.1 首页

- 新用户打开应用后，3 秒内能找到创意输入框和“开始制作”。
- 首页没有 8 阶段卡片、四项统计或大段技术说明。
- 最近项目可以一键打开。
- 未登录、Runtime 异常或图片能力缺失时，页面告诉用户下一步做什么。
- 用户输入在创建失败后仍然存在。

### 9.2 项目工作台

- 宽屏下能同时看到项目列表、制作记录和游戏预览。
- Pipeline 不再占据一整行大型卡片空间。
- 默认看不到模型、Reasoning、FPS、Thread ID 和方法名。
- 高级用户仍能找到所有现有参数和详细日志。
- 预览、素材、文件、审批、停止执行和设置功能全部保留。

### 9.3 技术质量

- 不新增 IPC channel。
- 不修改 Agent、Prompt、Skill 与媒体业务逻辑。
- 不增加前端依赖。
- 不引入 TypeScript 错误。
- Electron 开发模式和生产构建均可运行。
- 现有 Main 测试全部通过。

## 10. 验证命令

开发过程中使用：

```bash
npm run dev
npm run typecheck
```

阶段完成后使用：

```bash
npm run test
npm run build
npm run smoke:ui
```

最终交付前使用：

```bash
npm run verify
```

说明：`smoke:ui` 会构建并启动 Electron 进行截图验证；涉及真实 Codex 或媒体生成的 smoke 可能使用账户额度，本次纯 UI 验收不默认执行真实生成 smoke。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 一键开始会直接使用 Codex 或媒体额度 | 用户可能误触并产生用量 | 按钮文案明确为“开始制作”，执行中可停止；首次使用可显示一次简短提示 |
| 创建成功但 Agent 启动失败 | 留下草稿项目 | 保留项目并显示“再次开始”，不自动删除用户文件 |
| CSS 文件较大 | 改首页时影响设置或弹窗 | 使用页面级前缀，小步修改，每天做明暗主题和弹窗回归 |
| 窄屏无法容纳三栏 | 预览或输入区过小 | 窄屏改为单列，项目栏使用抽屉，预览通过 Tab 切换 |
| 技术日志隐藏过深 | 排查问题困难 | 保留统一“详细日志”入口，错误状态自动提供展开入口 |
| 默认项目名不理想 | 项目辨识度降低 | 从创意截取短名称，并允许在高级设置中修改 |

## 12. 提交与回退建议

建议按阶段提交，避免把所有 UI 变化压成一次大改动：

1. `refactor(ui): add simplified home workspace`
2. `feat(ui): start projects from a game idea`
3. `refactor(ui): simplify production workspace`
4. `refactor(ui): move advanced controls and logs`
5. `fix(ui): polish responsive states and accessibility`

每个提交都应能通过 `npm run typecheck`。如果某阶段出现问题，可以只回退对应阶段，不影响 Agent、项目数据和媒体能力。
